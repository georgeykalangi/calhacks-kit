# Hack Pitch

Judging moves fast. Judges remember what they can follow. Show, don't just tell.

## No file access?
Ask the team to paste `HACK.md`, or for: the user, the problem, the one journey, the hard
technical part, and what's mocked.

## Steps

### 1. Get the format
Read `HACK.md`. Ask for the judging format if it is not recorded: minutes per team, live stage or
expo table, whether judges rotate. Default to a 2-minute pitch at a table with 1-2 minutes of Q&A.

### 2. Write the script
Show the working product as early as possible: the demo starts within the first 20 seconds.

| Part | Time (2-min pitch) | Content |
|------|--------------------|---------|
| Open strong | 15s | One-sentence problem and the user. No team intros, no history. |
| Demo the flow | 60-75s | The MVP journey, live, narrated by outcome not by click. |
| Explain the tech | 20s | One technical decision or challenge that matters, with the architecture sketch. |
| Land the impact | 10-15s | Why it matters, what's new, what's next. |

Scale proportionally for longer slots. Write the script as spoken lines, not bullet points.
Disclose anything listed under Honesty in HACK.md, in one plain sentence during the demo.

### 3. Assign roles
- **Driver**: hands on the keyboard, follows the script, never improvises clicks.
- **Narrator**: tells the story while the driver demos.
- **Tech answers**: owns the architecture and hard-part questions.
- **Backup**: holds the backup video and a phone hotspot, watches the time.

Small teams combine roles. Write the names into HACK.md.

### 4. Prepare for Q&A
Write crisp 1-2 sentence answers to:
1. Who exactly is the user, and how do you know they have this problem?
2. What did you build yourselves versus use from libraries or APIs?
3. What's mocked or hardcoded?
4. What was the hardest technical problem, and how did you solve it?
5. How is this different from <the obvious existing product>?
6. What breaks first if 1,000 people use it?
7. What would you build with another week?
8. Which sponsor track does this fit, and how does it meet the requirement?

If an answer is "we don't know", say so honestly and with curiosity. Judges trust that.

### 5. Avoid what loses momentum
Long intro, click maze, jargon first, broken setup. Check the script for each and cut it.

### 6. Rehearse and set up
- Run the full pitch with a timer three times. Cut any line that pushes it over time.
- Demo machine: notifications off, extra tabs closed, zoom to 125%, already logged in with the
  seeded account, sample data loaded, backup video open in a tab, laptop charged.

Write the one-liner, roles, and script summary into the Pitch section of HACK.md.
Final reminders for the team: start on time, keep it honest, answer with curiosity, thank the judges.
